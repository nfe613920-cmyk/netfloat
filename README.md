# NetFloat

Linux 桌面网络、硬件与本地大模型监测悬浮窗。使用 C++17 / Qt 6 编写，适合在运行本地模型时观察网速、显存和上下文。

小型 Linux 桌面应用，实时显示网络上下行速度、GPU 使用率、显存与剩余量、GPU 温度及功耗、CPU 使用率、内存、CPU 温度，以及本地 llama-server 的 token 生成速度、上下文占用和上轮对话用量。界面使用无固定色相的中性深灰玻璃：默认底色约 45% 不透明，在支持 KDE 模糊效果的桌面上可模糊卡片背后的内容，壁纸颜色会自然透出。普通数据使用灰阶，只有告警使用提示色。默认以 245 × 83 像素的小窗常驻，悬停后展开完整面板，鼠标移开自动收起。可展开近 5 分钟趋势图，并设置显存余量提醒。网络默认每 750 毫秒刷新；模型生成中每 1 秒、空闲时每 2 秒刷新，断线后逐步延长重试间隔到最多 10 秒；其余项目每 2 秒刷新。无需额外后台服务。窗口可拖动，自动记住位置和设置。

## 功能概览

| 分类 | 显示内容 |
| --- | --- |
| 网络 | 上行、下行速度；实体 / TUN 网卡手动选择 |
| GPU | 使用率、已用 / 剩余显存、温度、功耗；AMD / NVIDIA |
| 系统 | CPU 使用率、内存占用、CPU 温度 |
| 本地模型 | token/s、提示词处理状态、上下文占用、新算 / 复用 token、上轮用量 |
| 提醒与趋势 | 显存余量提醒、上下文阈值提醒、近 5 分钟趋势 |
| 桌面交互 | 中性玻璃、KDE 背景模糊、边缘磁吸、贴边直角、悬停展开、系统托盘 |

## 构建和安装

### 依赖

- Linux、支持 C++17 的编译器、Bash 和 `pkg-config`。
- Qt 6 Widgets、Svg、Network 和 X11 的开发文件。
- 可选：KF6WindowSystem 开发文件，用于 KDE 背景模糊。
- NVIDIA 监测需要驱动提供的 `libnvidia-ml.so.1`；运行时动态加载，无需 CUDA 开发工具包。

构建脚本使用 `pkg-config` 检测依赖；各发行版的包名可能不同。背景模糊还需要桌面合成器支持并启用相应效果。

### 从源码运行

```bash
git clone https://github.com/nfe613920-cmyk/netfloat.git
cd netfloat
./build.sh
./netfloat
```

私有仓库需要先完成 GitHub 身份认证才能克隆。`build.sh` 在项目目录生成 `netfloat` 可执行文件；仓库不包含预编译二进制。

### 安装到当前用户

```bash
./install.sh
```

脚本会重新编译并安装程序到 `~/.local/bin/netfloat`，安装 SVG 图标和应用菜单入口；不需要 root。安装后可以从应用菜单的“工具”分类启动，或执行：

```bash
~/.local/bin/netfloat
```

安装脚本不配置开机自启。如有需要，可使用桌面环境的自启动设置添加 NetFloat。

## 使用

- 左键拖动悬浮窗；距离可用屏幕边缘 28 像素内会磁吸到边缘。贴边的角变为直角，拖离后恢复圆角；小窗和详细面板切换时仍保持贴边。悬浮窗不会占用任务栏，程序图标常驻系统托盘。
- 托盘或悬浮窗右键菜单的“玻璃透明度”提供 45%、57% 和 71% 三档底色不透明度。
- 小窗显示上行、下行、GPU 使用率、显存、模型速度和上下文百分比。鼠标在小窗停留约半秒会展开完整面板，移开后约一秒收起；托盘或悬浮窗右键菜单可取消“悬停展开（自动收起）”，将详细面板固定显示。
- 左键单击托盘图标可显示悬浮窗并展开／收起趋势图；双击悬浮窗也可展开／收起。托盘右键菜单提供显示／隐藏、趋势图和退出。
- 托盘或悬浮窗右键菜单可开启“紧凑显示”，隐藏详细面板中的上轮对话明细，使展开后的高度由 437 像素降为 391 像素；关闭后恢复，设置会记住。趋势图在两种尺寸下均可展开。
- 悬浮窗右键可选择网卡、显卡、显存提醒阈值、模型监测及本机接口端口、网络刷新间隔或退出。
- 默认优先选择 IPv4 默认路由对应的实体网卡；找不到时使用处于连接状态的实体网卡。菜单会标出实体和虚拟网卡。
- 上行显示在第一行，下行显示在第二行。单位使用 B/s、KiB/s、MiB/s，数值根据两次采样间的实际时间计算。
- GPU 使用率表示显卡计算／图形核心的忙碌百分比；显存是整张显卡的已用量，不仅限于大模型进程。GPU 区右上角显示剩余显存。AMD 显卡使用内核 sysfs，NVIDIA 显卡使用 NVML；没有可用数据时显示 `—`。
- CPU 使用率由 `/proc/stat` 两次采样的差值计算；内存已用量采用 `MemTotal - MemAvailable`，可回收缓存不算作已用。
- GPU 区集中显示 GPU 使用率、显存、温度和功耗；系统区显示 CPU 使用率、内存和 CPU 温度。AMD GPU 温度及功耗分别来自该显卡内核 hwmon 的 `temp1_input` 和 `power1_average`；NVIDIA 使用 NVML。CPU 温度来自 CPU 的 hwmon 传感器。不支持或不可读的指标显示 `—`。
- 显存余量提醒默认阈值为 2 GiB，可在右键菜单选择关闭或 1、2、4、8 GiB。余量低于阈值时，显存条和托盘图标变红，并在每次进入低余量状态时通知一次。重新高于阈值后，提醒状态自动复位。
- 展开趋势图可查看最近最多 5 分钟的上行、下行、GPU 占用及显存占用历史；数据在本机内存中按 2 秒间隔采样，不写入磁盘。刚启动时曲线会逐渐积累，展开状态会记住。
- “本地模型”区默认读取 `127.0.0.1:8080/slots`；可在右键菜单更改端口或关闭监测。仅从正在生成的任务读取 token 计数和任务编号，按采样间隔计算实时生成速度，多路任务显示合计 token/s。停止生成后，最近一次速度保留约 10 秒并标为“最近”；服务不可用时显示 `—`。不需要启用 `/metrics`，也不需要重启模型服务。
- 上下文行使用该接口的 `n_prompt_tokens` 和 `n_ctx`，显示当前槽位的已用 token、槽位上限及占用比例，生成过程中已用量随输出增长。默认按 `/slots` 返回的服务端槽位容量计算。若所用调用端另有限制，可在“本地模型 → 自定义上下文上限…”输入调用端设置的 token 数；进度和告警按两者较小值计算，两者不同则上下文行还显示“服”开头的服务端容量。输入 0 可恢复跟随服务端。新请求读入提示词时，`n_prompt_tokens` 是已处理的前缀，不是本轮完整上下文；这段时间悬浮窗标明并保留“上次上下文”，从首个输出 token 开始显示本轮真实值。多槽位时优先显示正在生成的槽位，其中取占用比例最高者；空闲时显示最近保留的槽位占用。启动脚本的 `-c` 是服务总上下文，启用多个并行槽位后，每槽位的上限可能小于脚本显示值，因此悬浮窗以 `/slots` 返回的实际上限为准。
- 上下文占用达到 80% 时进度条和托盘图标变黄，达到 90% 时变红，并在进入各级阈值时通知一次；阈值附近使用 2 个百分点的回退区间，避免数值抖动时重复通知。
- 模型状态区分提示词“读入中”、输出“生成中”和“空闲”。提示词行显示本次请求新处理的 token 数及从缓存复用的 token 数；多路任务时这两个数值合计显示。请求结束后保留最近一次提示词统计，供核对长上下文处理情况。
- “上轮”两行显示上一次观察到的请求的输入、输出、总 token 数和结束时槽位上下文。输入是调用端发送的完整提示词；如果调用端每轮重发历史消息，这个数包含历史消息，不仅是本轮新输入的文字。“新算／复用”行可用来区分本次实际处理与缓存复用。输出数由活跃任务计数和结束时槽位上下文推算，所以数值均标为“约”；极短的回复若在两次采样间完成，可能无法被观察到。刚启动或未观察到回复时显示等待提示。

### Clash / Mihomo TUN 模式

默认自动模式显示实际联网网卡的流量（例如 Wi-Fi 的 `wlp8s0f0`），包括代理传输、直连流量及协议开销，适合观察真实链路速度。若只想看经过 TUN 的逻辑流量，可右键手动选择 TUN 虚拟网卡（例如 `Meta`）。不要把实体网卡与 TUN 网卡的数值相加，同一批数据可能先后经过两者。应用显示整台电脑在所选网卡上的总流量，和 Clash 自身按连接统计的数值可能不同。

在有 XWayland 的 Wayland 桌面上，应用自动使用 XWayland，以便窗口定位和置顶。若显式设置 `QT_QPA_PLATFORM`，会遵从该设置。纯 Wayland 环境下，窗口置顶和定位取决于桌面环境的支持。

## 配置与数据来源

设置通过 Qt `QSettings` 保存在当前用户的配置目录（通常为 `~/.config/NetFloat/NetFloat.conf`），包含窗口位置、网卡 / 显卡选择和刷新设置。趋势历史只保存在内存中，退出后清空。程序读取 Linux `/proc`、`/sys` 和可选的 NVIDIA NVML；本地模型通过 HTTP 读取回环地址的 `/slots`。

### llama-server 接口要求

默认服务地址为 `http://127.0.0.1:8080/slots`。需要服务启用并提供可访问的 `/slots`，且返回槽位状态、token 计数和上下文容量。修改版 llama-server 的字段或统计语义若有变化，需要相应调整 `netfloat.cpp` 中的解析逻辑。它不依赖某个聊天客户端；显示的是模型服务槽位的用量。

模型 token/s 和上轮用量属于定时采样估算，不等同于调用端计费或精确请求日志。短于采样间隔的任务可能被漏掉；不支持该接口的服务会显示不可用状态。

## 已知限制

- GPU 指标取决于驱动和传感器权限，不可用时显示 `—`。
- Intel GPU 暂无专用监测实现。
- 玻璃模糊、置顶和窗口定位依赖桌面环境；透明度设置本身不保证有背景模糊。
- 网络统计是所选网卡的系统总流量，包含协议开销，不能当作某个应用的独立流量。
- 项目目前没有独立自动化测试套件；构建检查只能验证编译，硬件和桌面行为需要实际运行验证。
